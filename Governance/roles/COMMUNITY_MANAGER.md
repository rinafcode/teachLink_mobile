# Community Manager Role

## Purpose

The Community Manager (CM) fosters a healthy, inclusive, and vibrant community around TeachLink Mobile. They bridge the project and its users—teachers, developers, contributors, and stakeholders—ensuring communication flows both ways.

## Responsibilities

### Community Health & Growth
- **Welcome newcomers**: Monitor and respond to introductions, first issues, first PRs
- **Facilitate discussions**: Moderate GitHub Discussions, Discord/Slack, forums; keep conversations constructive
- **Identify & nurture leaders**: Spot active contributors; encourage progression to Reviewer/Triager/Committer
- **Conflict de-escalation**: First responder for CoC issues; enforce `CODE_OF_CONDUCT.md` with Maintainer escalation

### Communication & Outreach
- **Release announcements**: Coordinate with Release Manager for blog posts, social media, newsletter
- **Changelog highlights**: Translate technical changelogs into user-facing summaries
- **Roadmap communication**: Share project direction, priorities, and opportunities for input
- **Event coordination**: Organize/co-sponsor meetups, hackathons, office hours, conference presence

### Feedback Loops
- **Collect user feedback**: Surveys, issue analysis, support channels, social listening
- **Surface insights**: Monthly community health report to Maintainers (sentiment, pain points, feature requests)
- **Advocate for users**: Represent teacher/developer needs in planning meetings

### Moderation Authority
- **Enforce CoC**: Remove violating content; temp-ban repeat offenders (with Maintainer notification)
- **Manage discussion channels**: GitHub Discussions, Discord, Slack—archive stale, pin important
- **Handle spam/abuse**: Swift removal; report coordinated attacks to GitHub/Platform

## Moderation Authority

| Authority | Scope |
|-----------|-------|
| **Content removal** | Delete CoC-violating comments, issues, discussions |
| **User sanctions** | Temporary mute/ban (24h–30d); permanent ban requires Maintainer consensus |
| **Thread locking** | Lock heated/unproductive threads with public explanation |
| **Label management** | Apply `community`, `help-wanted`, `good-first-issue`, `duplicate`, `wontfix` |
| **Event management** | Create/manage community events, office hours, AMAs |

*CM does **not** have: merge rights, review approval, release authority, governance voting, or financial authority.*

## Appointment Process

1. **Nomination**: Any Maintainer nominates a community member with:
   - **Demonstrated community leadership**: 12+ months active; helps newcomers; de-escalates conflicts
   - **Communication skill**: Clear, empathetic, culturally aware writing
   - **Platform familiarity**: GitHub, Discord/Slack, social media, newsletter tools
   - **Impartiality**: No CoC violations; trusted by diverse community segments
2. **Discussion**: 14-day discussion period (community input encouraged)
3. **Approval**: Maintainer consensus (no objections) or 2/3 majority vote
4. **Onboarding**: Access to moderation tools, analytics, communication channels, brand assets

## Term & Succession

- **Term**: 1 year, renewable with Maintainer consensus
- **Transition**: 30-day handoff with outgoing CM
- **Interim**: Maintainers appoint interim within 14 days if role vacated

## Relationship to Other Roles

| Role | Interaction |
|------|-------------|
| **Maintainers** | Escalate CoC issues; receive community health reports; align on messaging |
| **Release Manager** | Coordinate release announcements, blog posts, social media timing |
| **Docs Lead** | Coordinate tutorial content, onboarding docs, event documentation |
| **Security Officer** | Coordinate security disclosure communications (public messaging) |
| **Working Group Leads** | Help recruit participants; promote WG outputs to community |
| **Reviewers/Triagers** | Surface community pain points from issue/PR interactions |

## Community Health Metrics

CM tracks and reports monthly:
- **Growth**: New contributors, new issue authors, discussion participants
- **Retention**: 30/90-day contributor return rate
- **Sentiment**: Positive/negative/neutral ratio in discussions
- **Response time**: Time to first response on issues, discussions, support channels
- **CoC incidents**: Count, resolution time, outcomes

## Recognition

- Listed in `Governance/RECOGNITION.md` and project website
- Community Manager badge on GitHub profile
- Annual "Community Builder" award
