# Emeritus Role

## Purpose

The Emeritus role recognizes individuals who have made significant, sustained contributions to TeachLink Mobile and wish to step back from active duties while maintaining a formal connection to the project.

## Eligibility

An individual may be granted Emeritus status if they meet **all** of the following criteria:

1. **Minimum tenure**: Served in an official governance role (Maintainer, Committer, Reviewer, Triager, Working Group Lead, Treasurer, Security Officer, Release Manager, Community Manager, or Docs Lead) for at least **2 years**.
2. **Substantial impact**: Demonstrated significant, sustained contributions to the project's technical direction, community health, or operational stability.
3. **Good standing**: Departed their active role in good standing with no unresolved Code of Conduct violations.
4. **Voluntary transition**: Requested Emeritus status voluntarily or was nominated by a current Maintainer.

## Nomination & Approval Process

1. **Nomination**: Any Maintainer may nominate an eligible individual by opening a GitHub issue in the governance repository using the "Emeritus Nomination" template.
2. **Discussion**: A 14-day discussion period allows community feedback.
3. **Approval**: Requires **consensus of Maintainers** (no objections after discussion period) or a **2/3 majority vote** of Maintainers if consensus cannot be reached.
4. **Announcement**: Upon approval, the Maintainers announce the new Emeritus member in the project's communication channels.

## Retained Privileges

Emeritus members retain the following:

| Privilege | Description |
|-----------|-------------|
| **Governance archive access** | Read access to private governance repositories and discussion archives |
| **Advisory voice** | May participate in governance discussions; opinions carry weight but no formal vote |
| **Mentorship** | Listed as available for mentorship in CONTRIBUTING.md |
| **Emeritus badge** | Displayed on GitHub profile and project website |
| **Communication channels** | Access to Maintainer communication channels (read-only for sensitive topics) |
| **Historical context** | Consulted for historical decisions and institutional knowledge |

## Removed Privileges

Emeritus members **do not** retain:

| Privilege | Description |
|-----------|-------------|
| **Voting rights** | No vote in Maintainer elections, role appointments, or policy changes |
| **Merge/commit rights** | No direct push or merge access to protected branches |
| **Review authority** | No binding approval on PRs or governance proposals |
| **Security access** | No access to security vulnerability reports or embargoed information |
| **Financial authority** | No spending authority or budget oversight |
| **Operational duties** | No on-call, triage, release, or incident response obligations |
| **Working group authority** | No authority to create or lead working groups |

## Duration & Review

- **Indefinite duration**: Emeritus status does not expire automatically.
- **Annual review**: Maintainers review Emeritus roster annually to confirm continued alignment with project values.
- **Voluntary resignation**: Emeritus members may resign at any time by notifying Maintainers.
- **Revocation**: Status may be revoked by Maintainer consensus for Code of Conduct violations or actions harmful to the project.

## Re-activation

An Emeritus member may request re-activation to an active role by:

1. Submitting a request to Maintainers
2. Demonstrating renewed capacity for active duties
3. Receiving Maintainer consensus for the specific role

Re-activation grants only the requested role, not all previous roles.
